# PLAN — Локальный голосовой тренажёр английского

Голосовой разговор с анимированным персонажем в браузере. Модель поправляет ошибки,
ведёт программу обучения, по запросу объясняет правила. Всё локально, в Docker,
Ollama — нативно на Windows (GPU), остальное (STT/TTS/VAD) — на CPU в одном app-контейнере.

## Архитектура (зафиксировано)

```
Браузер (getUserMedia, Web Audio, персонаж)
   │  WebSocket (аудио ⇄ аудио, бинарные кадры + JSON)
   ▼
app-контейнер (CPU-only, FastAPI)
   VAD (Silero, через faster-whisper vad_filter)
     → STT (faster-whisper, CPU, language из UI)
       → Оркестратор (режим = system-prompt, прогресс из SQLite)
         → LLM (Ollama, нативно на хосте, GPU)  http://host.docker.internal:11434
           → TTS (Piper, CPU, по клаузам)
             → аудио обратно в браузер по WebSocket
```

- Ollama НЕ в Docker (нативно, сама берёт GPU). app ходит на `host.docker.internal:11434`.
- Аудио целиком в браузере, в контейнер не пробрасывается.
- Язык ВВОДА (Whisper `language`) — переключатель EN/RU в UI, шлётся с каждым аудио.
- Язык ОТВЕТА — только из system-prompt режима (разговор=EN, объясни=RU).

## Сквозной сценарий приёмки

Зажать пробел → сказать фразу → персонаж listening → отпустить → thinking → потёк текст ответа
→ speaking с озвучкой по клаузам → idle. Tab переключает EN/RU (виден бейдж). Кнопка режима
меняет поведение (разговор EN / объясни правило RU). Прогресс пишется в `data/progress.db`.

## Железо

- Ноут (dev): любая машина, лёгкая модель, Ollama на CPU — проверяем логику.
- Целевой ПК: GTX 1050 Ti, 4 ГБ VRAM. На GPU только LLM (7B Q4). STT/TTS/VAD — CPU.
- Ничего железозависимого не хардкодить — всё в `.env`.
